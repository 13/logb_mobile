# Release 0.13.0: updater hardening, a decision on database encryption, and review clean-up — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> Status: not started. Execute on branch `release-0.13.0` from `main` after v0.12.0. Chosen by the user 2026-09-15 (items C7, C8, D).
> Sources: the final reviews of 0.7.0, 0.7.1 and 0.8.0 (open Minors recorded in `.superpowers/sdd/archive-0.7.0/progress.md`, `archive-0.7.1/progress.md` and the 0.8.0 ledger), and the code at 0.8.0:
> - `res/xml/network_security_config.xml` trusts user-installed CAs for every host (needed for self-hosters with an internal CA) — including GitHub, where the updater fetches the release list and APK.
> - `GitHubRelease.apk` takes the first asset ending in `.apk`.
> - `InstallResultReceiver` starts Android's install confirmation from the receiver; Android 14+ can block that background activity start when the user left the app during the session copy, and the Updates row then waits forever on "Android will ask you to confirm".
> - Database encryption: the mirror uses Room with `BundledSQLiteDriver`; SQLCipher for Android plugs in through `SupportSQLiteOpenHelper.Factory`, which a driver-configured Room does not use — adopting it means leaving the bundled driver, which this app moved to on purpose (see memory: `withTransaction` crashes with a driver-configured Room; the code uses `useWriterConnection`). That makes C8 a decision first, not a migration.

**Goal:** The updater trusts only system CAs for GitHub, installs the APK the release names for its version, and recovers when Android blocks its confirmation; database encryption gets a written, measured go/no-go; the open review Minors that change behaviour or add real coverage are fixed.

**Architecture:** Configuration and small code changes, each with its own test; the encryption work is a spike on a throwaway branch that produces a decision document and numbers, and nothing merges from it without the user's decision.

**Tech Stack:** As 0.12.0. The spike may add `net.zetetic:sqlcipher-android` on its own branch only.

## Global Constraints

- GitHub hosts `api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com` trust system CAs only; every other host keeps today's system + user CAs.
- The APK installed is the asset named `LogB-<version>.apk` for the release's tag version; a release without that asset is `NO_APK` (the page link stays offered).
- A blocked confirmation must never leave the row without an action: after returning to the app while installing, the row offers **Open the install confirmation**.
- Encryption: no change to the shipped database format in this release.
- Every behaviour change has a test; lint `warningsAsErrors`; wording en/de.
- Default version `0.13.0` / `1300`.

### Task 1: GitHub trusts system CAs only

**Files:** Modify `app/src/main/res/xml/network_security_config.xml`; Test `app/src/test/kotlin/dev/logb/android/feature/update/NetworkSecurityConfigTest.kt`

- [ ] **Step 1: Failing test** — parse the XML (`javax.xml.parsers.DocumentBuilderFactory` on `app/src/main/res/xml/network_security_config.xml` via the test's working directory) and assert: a `domain-config` exists whose `domain` elements (with `includeSubdomains="false"`) are exactly the four GitHub hosts, whose `trust-anchors` contain `certificates src="system"` and not `src="user"`, and that `base-config` still contains both `system` and `user`.
- [ ] **Step 2: Implement**

```xml
    <!--
      The in-app updater fetches the release list and the APK from GitHub. A user-installed CA (an MDM
      profile, a proxy root) must not be able to rewrite what an update is, so these hosts trust the
      system store alone. The signing-certificate check would still refuse a forged APK; this keeps the
      version, the checksum and the file name honest too.
    -->
    <domain-config>
        <domain includeSubdomains="false">api.github.com</domain>
        <domain includeSubdomains="false">github.com</domain>
        <domain includeSubdomains="false">objects.githubusercontent.com</domain>
        <domain includeSubdomains="false">release-assets.githubusercontent.com</domain>
        <trust-anchors>
            <certificates src="system" />
        </trust-anchors>
    </domain-config>
```

inside `<network-security-config>`, after `base-config`.
- [ ] **Step 3:** test PASS, lint green; commit `fix: GitHub requests for updates trust only the system's certificate authorities`.
