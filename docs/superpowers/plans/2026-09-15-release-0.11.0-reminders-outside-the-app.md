> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> Status: executed 2026-09-15. Deviations from this plan, in the order they arose:
> - `ShareInbox` carries a `LaunchRequest(target, objectUuid)` instead of a bare `LaunchTarget`, so the Reminders/Reading targets know which object to open.
> - A notification's *Log reading* action gets its own PendingIntent request code, not shared with the content tap (extras would otherwise be dropped by `filterEquals`).
> - `ReminderActions` restores the session itself (a process started cold for a broadcast or an update may not have one yet) and never lets an exception cross the receiver/widget boundary, so a bad write is reported rather than crashing the app silently.
> - Two lock-privacy fixes beyond the plan's scope: `LockPolicy.shouldRecheckForTarget` re-checks the gate without ignoring the grace period, and a synchronous pre-check at `onForeground` closes a pre-existing gap where resuming from the launcher or Recents after a timeout showed the logbook until DataStore answered.
> - `DigestPlan.idFor` uses the full positive hash of the reminder uuid (not `% 1e6`, which collided) and the summary says "and N more" only when children are actually hidden (more than five due), never for a plain multi-item list.
> - Widget privacy (locked shows only a count, no names) is covered by a `DueWidgetContentTest` using `androidx.glance:glance-appwidget-testing`, beyond the plan's own `DueWidgetStateTest`.
> - `WidgetRefresher` adds an immediate, undebounced refresh for the lock toggle and sign-out (privacy-sensitive: must not wait) alongside the plan's ~500 ms debounced refresh for sync/write/digest bursts.
> - The user's own bug report landed in the same branch: Navigation Compose's default crossfade double-exposed the old screen on every push/pop, fixed with slide transitions and an opaque per-destination background, plus a separate fix so a bottom-bar tap switches tabs instantly even from a screen pushed deep in a stack (a first attempt reset its flag one frame too early; a Robolectric UI test caught it).
> - Device verification (emulator `r8verify34`): actions offline, the grouped digest (three children + summary, reading child action-only), Done from the notification shade, Snooze while offline with the op queued and synced after, tapping a body/`Log reading`, the widget placed and refreshed live after sync/lock/sign-out, and the slide/instant-tab transitions were all verified on-device. **Goal:** Due reminders can be marked done or snoozed straight from the notification, reading reminders open the reading form from it, and a home-screen widget shows what is due with a one-tap done.

**Architecture:** A pure `DigestPlan` decides which notifications exist (one per due reminder up to five, plus a group summary when there are several) and what actions each carries; `ReminderNotifier` renders a plan. A `ReminderActionReceiver` and the widget's `ActionCallback` both call one `ReminderActions` singleton, so the notification and the widget do the same thing. The widget (Glance 1.2.0, as apexweather) renders a pure `DueWidgetState` built from `DueListModel` and the lock setting, and is refreshed after syncs, local writes, digest runs and at midnight.

**Tech Stack:** As 0.10.0, plus `androidx.glance:glance-appwidget` and `glance-material3` 1.2.0.

## Global Constraints

- Actions: service reminder → **Done** (`ReminderRepository.done(uuid, null)`) and **Snooze 7 days** (`snooze(uuid, 7)`); reading reminder → **Log reading** only (opens `ReadingForm(objectUuid)`), never Done.
- One due reminder → one notification with its actions, no summary. Two or more → one child per reminder for the first five (the digest's order) plus a group summary ("and N more" when more than five). Stable notification ids per reminder uuid; the summary keeps id `1`.
- Actions work offline, write through the op queue, cancel their own notification, and never open the app or ask for the app lock.
- Widget: up to five rows of reminders due or due within seven days (object name, title, when); a row tap opens that object's reminders tab; a check button marks a service reminder done through `ReminderActions`; reading rows have no check. Smallest size shows the count and the first row. With the app lock enabled (`LockPrefs`), the widget shows only the count ("3 due") and no names.
- Refresh the widget after every successful sync, every local write, every digest run, and once after midnight.
- Wording: new strings in `values/strings.xml` and `values-de/strings.xml`. Lint `warningsAsErrors`.
- Default version `0.11.0` / `1100`. Device checks only on an emulator via `adb -s emulator-5554`.

```kotlin
package dev.logb.android.core.notify

import dev.logb.android.feature.reminders.DueItem

enum class NotificationAction { Done, Snooze, LogReading }

data class ChildNotification(val id: Int, val reminderUuid: String, val objectUuid: String, val title: String, val text: String, val actions: List<NotificationAction>)

data class DigestNotifications(val summary: DigestText?, val children: List<ChildNotification>)

/** Which notifications the digest posts and what each can do; pure, so the phrasing and grouping are tested without a device. */
object DigestPlan {
    const val MAX_CHILDREN = 5
    const val SUMMARY_ID = 1
    private const val ID_BASE = 1_000

    fun plan(items: List<DueItem>, dueWord: String, upcomingWord: (Long) -> String, more: (Int) -> String): DigestNotifications {
        if (items.isEmpty()) return DigestNotifications(null, emptyList())
        val children = items.take(MAX_CHILDREN).map { item ->
            val r = item.view.reminder
            ChildNotification(
                id = idFor(r.uuid), reminderUuid = r.uuid, objectUuid = item.objectUuid,
                title = "${item.objectName}: ${r.title}",
                text = if (item.view.due) dueWord else upcomingWord(item.view.soonestDays ?: 0),
                actions = if (r.kind == "reading") listOf(NotificationAction.LogReading) else listOf(NotificationAction.Done, NotificationAction.Snooze),
            )
        }
        val summary = if (items.size > 1) Digest.text(items, dueWord, upcomingWord, more) else null
        return DigestNotifications(summary, children)
    }

    /** Stable per reminder and clear of the summary's id. */
    fun idFor(reminderUuid: String): Int = ID_BASE + (reminderUuid.hashCode() and 0x7FFFFFFF) % 1_000_000
}
```

`ReminderActions.kt`:

```kotlin
package dev.logb.android.core.notify

/** Done and snooze from outside the app (notification, widget): the same writes the app makes, then the notification goes. */
class ReminderActions(
    private val done: suspend (String) -> Unit,
    private val snooze: suspend (String) -> Unit,
    private val cancel: (String) -> Unit,
) {
    suspend fun done(reminderUuid: String) { done.invoke(reminderUuid); cancel(reminderUuid) }
    suspend fun snooze(reminderUuid: String) { snooze.invoke(reminderUuid); cancel(reminderUuid) }
}
```

`NotifyModule` (`di/NotifyModule.kt`): `@Provides @Singleton fun reminderActions(repos: Repositories, notifier: ReminderNotifier) = ReminderActions({ repos.reminderRepository.done(it, null) }, { repos.reminderRepository.snooze(it, 7) }, notifier::cancel)`.

`ReminderActionReceiver.kt`:

```kotlin
package dev.logb.android.core.notify

import android.content.BroadcastReceiver
import android.content.Context
import android.content.Intent
import dagger.hilt.EntryPoint
import dagger.hilt.InstallIn
import dagger.hilt.android.EntryPointAccessors
import dagger.hilt.components.SingletonComponent
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.SupervisorJob
import kotlinx.coroutines.launch

@EntryPoint
@InstallIn(SingletonComponent::class)
interface ReminderActionsEntryPoint { fun actions(): ReminderActions }

/** Done / Snooze tapped on a notification: written offline through the op queue, no activity, no lock. */
class ReminderActionReceiver : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        val uuid = intent.getStringExtra(EXTRA_REMINDER) ?: return
        val actions = EntryPointAccessors.fromApplication(context.applicationContext, ReminderActionsEntryPoint::class.java).actions()
        val pending = goAsync()
        CoroutineScope(SupervisorJob() + Dispatchers.IO).launch {
            try {
                when (intent.action) {
                    ACTION_DONE -> actions.done(uuid)
                    ACTION_SNOOZE -> actions.snooze(uuid)
                }
            } finally {
                pending.finish()
            }
        }
    }

    companion object {
        const val ACTION_DONE = "dev.logb.android.REMINDER_DONE"
        const val ACTION_SNOOZE = "dev.logb.android.REMINDER_SNOOZE"
        const val EXTRA_REMINDER = "reminder"
    }
}
```
