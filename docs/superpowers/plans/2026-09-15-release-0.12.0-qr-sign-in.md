> Starting points (logb `origin/main` at 0.8.5): login is `api::auth::login` with `auth::check_login_rate(&state, auth::client_ip(&state, &headers, peer))?`; tokens come from `auth::new_api_token()`, `auth::hash_api_token`, `auth::token_prefix`; migrations are `migrations/sqlite/0014_own_types.sql` and `migrations/postgres/0005_own_types.sql`; `rand 0.10`, `sha2 0.11`, `base64ct 1.8` are dependencies. App (0.8.0): `ServerCapabilities.pairing` is true for servers ≥ 0.9.0; `SessionRepository.signIn` stores token and `ServerRecord`; `MainActivity` hands every intent to `ShareInbox.offer`.

**Goal:** On the web's Account page a signed-in person shows a QR code; the phone's first screen scans it and is signed in, without typing an address or a password.

**Architecture:** logb gains a `pairing_codes` table and two endpoints: `POST /api/auth/pair` (password session only, like token creation) returns a short-lived single-use code, the pairing URI and its QR as SVG; `POST /api/auth/pair/redeem` (no auth, rate-limited like login) swaps the code for a named API token. The app parses `logb://pair?server=…&code=…` from a scan (ZXing) or a deep link, checks the server, redeems, and stores the session exactly as a password sign-in does.

**Tech Stack:** logb: Rust (axum, sqlx), `qrcode` crate (SVG, no image features). App: as 0.11.0 plus `com.journeyapps:zxing-android-embedded` (QR only).

## Global Constraints

- Code: 32 random bytes, base64url without padding; only its SHA-256 is stored; valid 5 minutes; single use (the redeem marks it used in the same transaction that creates the token); creating a code needs an interactive session (`SessionUser`), exactly like `create_token`.
- Redeem: unknown, expired and used codes all answer the same `401`; redeem is rate-limited with `check_login_rate` keyed by `client_ip`; the token is named `LogB Android · <device name>` (1–64 chars, trimmed).
- Pairing URI: `logb://pair?server=<percent-encoded base URL with trailing slash>&code=<code>`. The app accepts only `https://` servers from a QR code, plus `http://` hosts that are private LAN addresses or `localhost` (a QR must not silently point a phone at an arbitrary cleartext host).
- The app offers "Scan QR code" only on the server screen, asks for the camera permission on tap, declares `<uses-feature android:name="android.hardware.camera" android:required="false"/>`, and when already signed in asks before replacing the account.
- A 404 from redeem means an older server: "This server does not support QR sign-in (needs LogB 0.9.0). Sign in with your password."
- Web wording in logb's `en.ts`/`de.ts`; app wording in `values/` and `values-de/`. Lint (app) `warningsAsErrors`; logb `cargo clippy -- -D warnings` and its test suites green.
- Versions: logb `0.9.0`; app `0.12.0` / `1200`.

- [ ] **Step 1: Failing tests**

```kotlin
class PairingLinkTest {
    @Test fun `parses a pairing uri`() =
        assertEquals(PairingLink("https://logb.example/", "abc_-9"), PairingLinks.parse("logb://pair?server=https%3A%2F%2Flogb.example%2F&code=abc_-9"))

    @Test fun `normalises the server to one trailing slash`() =
        assertEquals("https://logb.example/x/", PairingLinks.parse("logb://pair?server=https%3A%2F%2Flogb.example%2Fx&code=c")!!.serverUrl)

    @Test fun `http only for localhost and private lan addresses`() {
        assertEquals("http://192.168.1.5:8080/", PairingLinks.parse("logb://pair?server=http%3A%2F%2F192.168.1.5%3A8080&code=c")!!.serverUrl)
        assertEquals("http://localhost:8090/", PairingLinks.parse("logb://pair?server=http%3A%2F%2Flocalhost%3A8090&code=c")!!.serverUrl)
        assertNull(PairingLinks.parse("logb://pair?server=http%3A%2F%2Fexample.org&code=c"))

    @Test fun `anything else is not a pairing link`() {
        listOf("https://logb.example", "logb://other?server=https%3A%2F%2Fa&code=c", "logb://pair?code=c", "logb://pair?server=https%3A%2F%2Fa", "logb://pair?server=ftp%3A%2F%2Fa&code=c", "")

    }
}
```
